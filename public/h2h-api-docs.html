H2H API v1 — Host to Host

Dokumentasi H2H API

Integrasikan sistem/toko kamu langsung ke katalog produk MyMarket: produk marketplace biasa dan Topup Game, lengkap dengan skema input per produk. Order otomatis dipotong dari saldo akunmu — kalau saldo kurang, sistem otomatis membuatkan QRIS dan order akan lanjut diproses sendiri begitu QRIS-nya dibayar.

Base URL: https://api.mymarket.web.id/api/h2h/v1
Auth: header X-API-Key
Format: JSON

Mulai Cepat

Empat langkah dari nol sampai order pertama berhasil.

1
Buat API Key. Login ke akun MyMarket, buka menu H2H API, lalu klik generate. Key hanya tampil sekali — simpan di tempat aman (server, bukan di aplikasi klien).
2
Tes koneksi. Panggil GET /balance. Kalau dapat saldo akunmu, Base URL dan API Key sudah benar.
3
Ambil katalog. Panggil GET /catalog (dan GET /catalog/topup/:category_key untuk Topup Game) untuk mendapat product_variant_id, service_code, harga, dan field input yang wajib diisi.
4
Buat order. Kirim POST /order dengan ref_id unik dari sistemmu, lalu pantau hasilnya lewat webhook atau GET /order/:id.
curl — tes koneksi
curl "https://api.mymarket.web.id/api/h2h/v1/balance" \
  -H "X-API-Key: h2h_live_xxxxxxxxxxxxxxxxxxxxxxxx"

Base URL

Semua endpoint H2H diakses lewat host API MyMarket berikut, selalu dengan HTTPS.

base url
https://api.mymarket.web.id/api/h2h/v1
Gunakan host API di atas, bukan domain website (tempat kamu login) dan bukan domain layanan lain. Kalau respons yang kamu terima berupa halaman HTML atau 404 dari host lain, hampir pasti Base URL-nya salah.

Semua path di dokumentasi ini ditulis relatif terhadap Base URL. Contoh: GET /balance berarti GET https://api.mymarket.web.id/api/h2h/v1/balance.

Autentikasi

Sertakan API Key di header X-API-Key pada setiap request ke /api/h2h/v1/*. Satu akun punya satu key aktif. Semua order dipotong dari saldo akun pemilik key, jadi pastikan saldo cukup atau siap dibayar via QRIS otomatis.

Format Respons

Semua respons berupa JSON dengan field success. Ada dua lapis hasil yang perlu kamu bedakan:

KondisiBentuk responsArtinya
Ditolak sebelum order dibuatHTTP 200, "success": false + messageInput kurang/salah, produk habis, dll. Order belum terbentuk dan tidak ada saldo terpotong — aman dicoba lagi.
Order terbentukHTTP 200, "success": true + dataCek data.status: bisa success, partial, failed, atau awaiting_payment.
Masalah autentikasi / akses / limitHTTP 401 / 403 / 429Lihat bagian Kode Error.
Error serverHTTP 500Coba lagi sebentar. Untuk order, cek status pakai ref_id sebelum membuat ulang.
json — ditolak (success:false)
{ "success": false, "message": "Zone ID wajib diisi" }
success: true tidak selalu berarti order berhasil. Order yang terbentuk lalu gagal diproses tetap dibalas success: true dengan data.status = "failed" dan alasannya di data.result.message. Selalu periksa data.status.

Modul Lain: PPOB, App Premium, Sosmed, Nomor OTP, Subdomain

Selain produk general dan topup, semua menu di web lainnya juga bisa dipesan lewat H2H. Harga, validasi, dan refund otomatis sama persis dengan order dari web. Harga di katalog sudah termasuk diskon H2H. Modul yang dimatikan owner akan menjawab 403.

Endpoint katalog

EndpointIsi
GET /catalog/ppobDaftar kategori PPOB. Item per kategori: GET /catalog/ppob/:category_key
GET /catalog/apppremSemua produk App Premium (item_id, harga, stok, input_fields)
GET /catalog/socmedDaftar kategori Sosmed dari semua server. Layanan per kategori: GET /catalog/socmed/:category_key?server=1
GET /catalog/nokosPenawaran Nomor OTP yang ada stok (offer_id, harga)
GET /catalog/subdomainDomain yang tersedia beserta harga

Body order per modul

Semua dikirim ke POST /order dengan product_type sesuai modul, plus ref_id opsional.

product_typeField
ppobcategory_key, product_code, target_id (nomor/ID pelanggan), quantity (nominal, hanya untuk produk open_denom)
apppremitem_id, quantity (default 1, maks 20), order_values (objek, sesuai input_fields item)
socmedserver, category_key, service_id, target_id (link/username), quantity, comments (khusus layanan komentar custom, satu per baris)
nokosoffer_id dari katalog. Satu akun hanya boleh punya satu order OTP aktif
subdomaindomain, name, ip, proxied (true/false, opsional)

Contoh order PPOB (cURL)

curl
curl -X POST https://api.mymarket.web.id/api/h2h/v1/order \
  -H "X-API-Key: h2h_live_xxxxxxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"product_type":"ppob","category_key":"pulsa","product_code":"TSEL10","target_id":"081234567890","ref_id":"TRX-0001"}'
Status akhir dari provider (mis. pulsa sukses, OTP masuk, akun App Premium terkirim) tampil di result.provider_status dan result.detail saat kamu memanggil GET /order/:id. Untuk topup game, statusnya ada di result.status. Begitu status akhir terdeteksi, webhook order.completed atau order.failed dikirim satu kali.

Buat Order

Membuat order baru. Kirim ref_id milikmu sendiri supaya request aman diulang (idempotent) — kalau ref_id yang sama dikirim lagi, API mengembalikan order yang sudah ada, bukan membuat order baru.

Body — produk general

FieldTipeKet.
product_typestring"general" (default kalau tidak dikirim)
product_variant_idwajibstringDari endpoint Katalog
quantityopsionalnumberDefault 1, minimal 1, maksimal 50. Tiap unit diproses satu per satu
ref_idopsionalstringID transaksi milikmu, maks 100 karakter, unik per akun

Body — produk topup game

FieldTipeKet.
product_typewajibstringSelalu "topup"
category_keywajibstringDari endpoint Katalog
service_codewajibstringDari endpoint Item Topup Game
target_idwajib*stringUser ID / nomor tujuan
zone_idtergantung gamestringZone/Server ID — hanya untuk game yang meminta (lihat input_fields)
additional_dataopsionalstringData tambahan untuk layanan tertentu (mis. joki), bila diminta
ref_idopsionalstringID transaksi milikmu, maks 100 karakter, unik per akun
* Field mana saja yang wajib ditentukan oleh input_fields kategori (properti required: true). Kalau ada yang kosong, API membalas success:false dengan pesan seperti Zone ID wajib diisi.

Alur & Status Order

Status yang bisa muncul di data.status:

StatusArtinyaTindakan
awaiting_paymentSaldo kurang; QRIS sudah dibuat dan menunggu pembayaran.Bayar QRIS sebelum payment.expired_at. Order lanjut otomatis setelah terbayar.
processingOrder sedang diproses (status sementara, sesaat setelah dibayar/dipotong saldo).Tunggu beberapa detik lalu cek status lagi.
successOrder selesai. Topup: diterima provider & saldo terpotong. General: semua unit berhasil.Ambil hasil dari result.
partialGeneral dengan quantity > 1: sebagian unit berhasil, sebagian gagal.Cek tiap result.units[]. Hanya unit berhasil yang ditagihkan.
failedOrder gagal diproses. Saldo yang sempat terpotong dikembalikan.Baca result.message. Buat order baru dengan ref_id baru bila perlu.

Alur singkat

1
Saldo cukup → order langsung diproses → respons berisi status akhir (success / partial / failed) dan webhook dikirim bila diatur.
2
Saldo kurang → respons berstatus awaiting_payment berisi QRIS → setelah dibayar order diproses otomatis → status berubah ke status akhir dan webhook dikirim bila diatur.
Jika QRIS kedaluwarsa tanpa dibayar, sistem tidak memproses order tersebut. Anggap order batal setelah expired_at lewat, dan kirim order baru dengan ref_id baru (memakai ref_id yang sama hanya akan mengembalikan order lama).

import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;

public class H2hWebhookVerifier {

    /** rawBody = isi body MENTAH persis seperti yang diterima (jangan di-serialize ulang). */
    public static boolean isValid(String rawBody, String signatureHeader, String webhookSecret) throws Exception {
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(webhookSecret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        byte[] digest = mac.doFinal(rawBody.getBytes(StandardCharsets.UTF_8));

        StringBuilder hex = new StringBuilder();
        for (byte b : digest) hex.append(String.format("%02x", b));

        return MessageDigest.isEqual(
                hex.toString().getBytes(StandardCharsets.UTF_8),
                (signatureHeader == null ? "" : signatureHeader).getBytes(StandardCharsets.UTF_8));
    }
}

Contoh Integrasi Lengkap

Klien kecil siap pakai yang membungkus semua endpoint, menangani respons non-JSON, dan menunjukkan pola aman untuk order: simpan ref_id lebih dulu, lalu cek status bila koneksi putus.

php
<?php
class MyMarketH2H
{
    private string $baseUrl = "https://api.mymarket.web.id/api/h2h/v1";

    public function __construct(private string $apiKey) {}

    private function request(string $method, string $path, ?array $body = null): array
    {
        $curl = curl_init();
        $opts = [
            CURLOPT_URL            => $this->baseUrl . $path,
            CURLOPT_CUSTOMREQUEST  => $method,
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_CONNECTTIMEOUT => 10,
            CURLOPT_TIMEOUT        => 60,
            CURLOPT_HTTPHEADER     => [
                "X-API-Key: " . $this->apiKey,
                "Content-Type: application/json",
                "Accept: application/json",
            ],
        ];
        if ($body !== null) {
            $opts[CURLOPT_POSTFIELDS] = json_encode($body);
        }
        curl_setopt_array($curl, $opts);

        $raw  = curl_exec($curl);
        $err  = curl_error($curl);
        $code = curl_getinfo($curl, CURLINFO_HTTP_CODE);
        curl_close($curl);

        if ($raw === false) {
            return ["success" => false, "network_error" => true, "message" => $err];
        }
        $json = json_decode($raw, true);
        if (!is_array($json)) {
            return ["success" => false, "http_code" => $code, "message" => "Respons bukan JSON (cek Base URL)"];
        }
        $json["http_code"] = $code;
        return $json;
    }

    public function catalog(): array                { return $this->request("GET", "/catalog"); }
    public function topupItems(string $key): array  { return $this->request("GET", "/catalog/topup/" . rawurlencode($key)); }
    public function balance(): array                { return $this->request("GET", "/balance"); }
    public function order(array $payload): array    { return $this->request("POST", "/order", $payload); }
    public function status(string $idOrRef): array  { return $this->request("GET", "/order/" . rawurlencode($idOrRef)); }
}

class MyMarketH2H {
  constructor(apiKey, baseUrl = "https://api.mymarket.web.id/api/h2h/v1") {
    this.apiKey = apiKey;
    this.baseUrl = baseUrl;
  }

  async request(method, path, body) {
    try {
      const res = await fetch(this.baseUrl + path, {
        method,
        headers: {
          "X-API-Key": this.apiKey,
          "Content-Type": "application/json",
          "Accept": "application/json",
        },
        body: body ? JSON.stringify(body) : undefined,
        signal: AbortSignal.timeout(60000),
      });
      const text = await res.text();
      let json;
      try { json = JSON.parse(text); }
      catch { return { success: false, httpCode: res.status, message: "Respons bukan JSON (cek Base URL)" }; }
      return { ...json, httpCode: res.status };
    } catch (err) {
      return { success: false, networkError: true, message: err.message };
    }
  }

  catalog()          { return this.request("GET", "/catalog"); }
  topupItems(key)    { return this.request("GET", "/catalog/topup/" + encodeURIComponent(key)); }
  balance()          { return this.request("GET", "/balance"); }
  order(payload)     { return this.request("POST", "/order", payload); }
  status(idOrRef)    { return this.request("GET", "/order/" + encodeURIComponent(idOrRef)); }
}

  if (o.status === "success") console.log("Selesai", o.result);
  else if (o.status === "failed") console.log("Gagal:", o.result.message);
  else if (o.status === "awaiting_payment") console.log("Bayar QRIS sebelum", o.payment.expired_at);
}

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

public class MyMarketH2H {
    private static final String BASE_URL = "https://api.mymarket.web.id/api/h2h/v1";

    private final String apiKey;
    private final HttpClient client = HttpClient.newBuilder()
            .connectTimeout(Duration.ofSeconds(10))
            .build();

    public MyMarketH2H(String apiKey) { this.apiKey = apiKey; }

    private HttpResponse<String> send(String method, String path, String jsonBody) throws Exception {
        HttpRequest.Builder b = HttpRequest.newBuilder()
                .uri(URI.create(BASE_URL + path))
                .timeout(Duration.ofSeconds(60))
                .header("X-API-Key", apiKey)
                .header("Content-Type", "application/json")
                .header("Accept", "application/json");

        if ("POST".equals(method)) b.POST(HttpRequest.BodyPublishers.ofString(jsonBody));
        else b.GET();

        return client.send(b.build(), HttpResponse.BodyHandlers.ofString());
    }

    public String catalog() throws Exception           { return send("GET", "/catalog", null).body(); }
    public String topupItems(String key) throws Exception { return send("GET", "/catalog/topup/" + key, null).body(); }
    public String balance() throws Exception           { return send("GET", "/balance", null).body(); }
    public String order(String json) throws Exception  { return send("POST", "/order", json).body(); }
    public String status(String idOrRef) throws Exception { return send("GET", "/order/" + idOrRef, null).body(); }

    public static void main(String[] args) throws Exception {
        MyMarketH2H api = new MyMarketH2H("h2h_live_xxxxxxxxxxxxxxxxxxxxxxxx");
        String refId = "TRX-" + System.currentTimeMillis(); // simpan di DB kamu SEBELUM request

        String json = "{"
                + "\"product_type\":\"topup\","
                + "\"category_key\":\"mobile-legends\","
                + "\"service_code\":\"ML86\","
                + "\"target_id\":\"123456789\","
                + "\"zone_id\":\"1234\","
                + "\"ref_id\":\"" + refId + "\""
                + "}";

        try {
            System.out.println(api.order(json));
        } catch (java.io.IOException timeoutOrNetwork) {
            // Order MUNGKIN sudah terbentuk. Cek dengan api.status(refId); jangan ganti ref_id.
            System.out.println(api.status(refId));
        }
    }
}

Harga Khusus H2H

Semua harga yang dikembalikan lewat H2H API (katalog, item topup, hasil order) sudah dihitung dengan diskon khusus H2H yang diatur owner toko — kamu tidak perlu menghitung ulang. Diskon ini otomatis dikreditkan kembali ke saldomu setelah order berhasil, jadi harga yang kamu lihat di respons API adalah harga akhir yang kamu bayar.

Member Gold: kalau akun pemilik API Key adalah Member Gold, semua harga di katalog dan order otomatis memakai harga khusus Gold (potongan Gold dihitung lebih dulu, lalu diskon H2H di atas). Field member_tier pada respons katalog menunjukkan tier akun kamu (bronze / gold). Katalog Gold dan Bronze berbeda, jadi selalu ambil katalog dengan API Key yang sama dengan yang dipakai untuk order.

Persentase diskon aktif bisa dilihat di data.discount_percent pada respons Katalog Produk. Nilainya dapat berubah sewaktu-waktu, jadi ambil katalog secara berkala bila kamu menampilkan harga di etalasemu sendiri.

PPOB: produk PPOB tidak ikut diskon persentase di atas, karena memakai potongan terpisah. Pada GET /api/h2h/v1/catalog/ppob, data.discount_percent bernilai 0 dan potongan khusus PPOB ada di data.discount (type: flat = nominal rupiah, percent = persen; value). Harga di katalog sudah final.

Weekly Diamond Pass Mobile Legends: item ini juga memakai potongan terpisah (tidak ikut diskon persentase global), tetapi harga di GET /api/h2h/v1/catalog/topup/:category_key tetap sudah final, jadi tidak perlu dihitung ulang.

Rate Limit

Batas request dihitung per API Key, dengan lapisan tambahan per alamat IP pengirim. Bila terlampaui, API membalas HTTP 429.

CakupanDihitung perBatas
Semua endpoint H2H (gabungan)API Key120 request per menit
GET /catalog dan GET /catalog/topup/:keyAPI Key10 request per menit
POST /orderAPI Key20 request per menit
Semua endpoint H2H (gabungan)IP300 request per menit
Request dengan API Key salah / tidak valid (401/403)IP20 kegagalan per 5 menit
Seluruh /api/* (gabungan)IP600 request per 15 menit
json · 429 Too Many Requests
{ "success": false, "code": "RATE_LIMITED", "message": "Terlalu banyak request untuk API Key ini. Coba lagi sebentar.", "retry_after": 17 }
Respons 429 menyertakan header Retry-After (detik) dan retry_after di body — tunggu selama itu sebelum mencoba lagi. Header RateLimit-Limit, RateLimit-Remaining, dan RateLimit-Reset ikut dikirim di setiap respons supaya kamu bisa memantau sisa jatah. Batas /api/* gabungan membalas 429 tanpa code/retry_after, jadi andalkan header Retry-After.
Simpan katalog di cache sisi kamu (misalnya 1–5 menit) daripada memanggil /catalog di setiap permintaan pengguna. Katalog di sisi server juga di-cache sekitar 30 detik, jadi angka stock_available bisa tertinggal beberapa detik; stok yang sebenarnya selalu dicek saat POST /order.
Request yang terus-menerus dikirim dengan API Key salah akan kena batas per IP. Pastikan header X-API-Key benar sebelum mengulang, dan jangan mencoba ulang tanpa jeda setelah 401.
